# 15. 범위 변경: 손질 수율 · 고정비(실제 이익) · 매입 기준 실제 원가

| 항목 | 내용 |
|------|------|
| 결정일 | 2026-11-18 |
| 상태 | 구현됨 (웹·API·DB) |
| 대체 | 01·02·03·05·06·07·08·09·10·11·12·13 문서의 "수율·인건비 제외" 조항 중 아래 범위 |
| 유지되는 제외 | 메뉴별 조리시간·인건비 배분, 판매량·실제 사용량 추정 |

## 1. 왜 바꿨나

1. **입력 부담:** 원래의 이론 vs 실제 비교(DF-A)는 재료별 실사를 전제로 했다. 1인 운영자는 매주 재고를 세지 않는다. 그래서 차별화 기능이 실제로는 가장 덜 쓰일 위험이 있었다.
2. **"진짜 남는 돈":** 공헌이익만으로는 운영자가 가장 궁금한 "이번 달 실제로 남았나"에 답하지 못했다.
3. **원가 과소:** 손질 손실을 무시하면 고기·채소 메뉴의 원가가 체계적으로 낮게 나왔다.

## 2. 손질 수율 (yieldRate)

- `Ingredient.yieldRate` (0 < r ≤ 1, 기본 1). 화면에서는 %로 입력한다.
- **레시피 투입량 = 손질 후 쓸 수 있는 양(가용량)**으로 정의한다.
- 가용 단가 = 구매 단가 ÷ r → 메뉴 원가, 시뮬레이션, 기여도, 주간 지표에 모두 반영된다 (`costing-context` 한 곳).
- 이론 vs 실제(DF-A): 실제 사용량은 구매 단위(원물) 기준이다. 그래서 이론량도 원물로 바꿔(가용량 ÷ r) 구매 단가로 비교한다.
- 가격 영향(DF-B): 이력은 구매 단가로 저장되어 있고, 비교할 때 **현재 수율**을 적용한다.
- 수율만 바꾸면 가격 이력이 생기지 않는다 (가격 변경이 아니기 때문).
- 프렙 `yieldQty`(산출량)와는 별개의 개념이다.

## 3. 고정비와 실제 이익

- `FixedCostItem` (LABOR / RENT / UTILITIES / OTHER, 월 금액). **메뉴에 배분하지 않는다.**
- 판매 기간 P&L (`GET /contribution-analysis` 응답의 `profitAndLoss`):
  - 기간 고정비 = Σ 월 금액 × 기간일수 ÷ (365/12)
  - 영업이익 = 총 공헌이익 − 기간 고정비
  - 공헌이익률 = 총 공헌이익 ÷ 매출
  - 손익분기 매출 = 기간 고정비 ÷ 공헌이익률 (이 기간의 **실제 판매 구성** 기준. 공헌이익률이 0 이하이면 null)
  - 안전한계율 = (매출 − 손익분기) ÷ 매출
- 고정비가 하나도 없으면 `status: "NO_FIXED_COSTS"`를 반환하고 금액을 가정하지 않는다.
- 세금·대출이자·감가상각은 포함하지 않는다. 화면 문구도 "순이익"이 아니라 "영업이익"을 쓴다.

## 4. 매입 기준 실제 원가 (재고 실사 없이)

- `PurchaseRecord` (일자, 금액, 거래처, 메모). 레시피 재료의 매입만 입력하도록 안내한다.
- `GET /purchase-variance?periodId=…[&openingInventory=&closingInventory=]`
  - 이론 원가 = Σ 판매량 × 레시피 가용량 × 가용 단가 (현재 마스터 기준)
  - 실제 원가 = 기간 매입 합계 (`PURCHASES_ONLY`, 근사)
    또는 기초재고 + 매입 − 기말재고 (`PURCHASES_WITH_INVENTORY`). **재고는 둘 다 있을 때만 적용한다.** 한쪽만 보내면 400.
  - 판매량이 없거나 매입이 없으면 `INSUFFICIENT_DATA`.
- **실사 우선순위 (`countPriorities`):** 이론 원가가 큰 순으로 누적 80%까지, 최대 5개를 반환한다. "이것만 세면 된다"는 안내에 쓴다. 재료별 정밀 비교(DF-A)는 이 재료들만 입력해도 동작한다.
- 판매 기간 `grain`에 `MONTH`를 추가했다. 매입 근사는 월 단위일수록 정확하다.

## 6. 남은 일

- 배달앱 정산서·POS 판매 파일 가져오기 (판매량 입력 자동화). 실제 파일 샘플 확보 후 진행.
- 매입 CSV/영수증 입력 보조.
- 고정비 이력(월별 변경) — 현재는 현재값으로 과거 기간도 계산한다.
- 수율 이력 — 현재는 현재값으로 과거 가격 영향을 계산한다.
